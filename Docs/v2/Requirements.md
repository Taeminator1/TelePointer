# 요구 사항 v2

v1 요구사항은 [v1/Requirements.md](../v1/Requirements.md) 참고 —
아래에 다시 적지 않은 항목은 v1 그대로 유지한다.

## 버전

- Minimum Deployments: macOS 26
- Swift: 6
- Tuist: 4.205.0

## 기능

### Pointer 이동

#### 방향 이동

- **방향**: 상 · 하 · 좌 · 우 4방향. 두 방향을 함께 누르면 대각선으로 간다
    - 서로 반대인 두 방향을 함께 누르면 제자리에 멈춘다 — 멈춘 동안에도 커서는 잡혀 있어 마우스로 밀리지 않는다. 하나를 떼면 곧바로 재개
- **입력 방식**: 홀드 — 누르고 있는 동안 계속 이동한다
- **정지 조건**: 셋 중 하나라도 걸리면 멈춘다
    - 누르고 있던 방향키를 모두 뗌
    - 단축키의 modifier가 풀림
    - 누른 지 5초 경과
    - 뒤의 둘은 키 릴리스를 놓쳤을 때 커서가 계속 날아가는 것을 막는 안전장치다.
      한 번 멈추면 키를 다시 눌러야 재개된다
- **화면 경계 처리**: 커서는 언제나 어느 한 화면 안에 머문다
    - 이어지는 구간에서는 인접 모니터로 그대로 넘어간다
    - 어느 화면에도 속하지 않는 좌표가 되면 가장 가까운 화면 안쪽으로 당긴다

#### 클릭

- 커서 위치에 **왼쪽 클릭**(⌃⌥X)과 **오른쪽 클릭**(⌃⌥V)을 발생시킨다
- 연타하면 더블 · 트리플 클릭으로 올라간다 — 간격은 시스템 설정의 값을 따른다
- **접근성 권한이 필요하다.** v1의 「세 기능 모두 접근성 권한이 필요 없음」 전제는 클릭에 한해 깨진다
- **배포 경로는 Mac App Store를 유지한다.** App Sandbox를 켠 채로 클릭이 동작하는 것을 확인했고
  entitlement 추가도 필요 없다. App Review 통과 여부는 확답이 없어 위험을 안고 간다 ([Notes.md](../Notes.md))

##### 권한 요청

- **앱은 권한을 확인하지 않고 그냥 클릭을 시도한다.** 권한이 없으면 macOS가 스스로 프롬프트를 띄우고,
  그때 앱이 손쉬운 사용 목록에 등록되어 사용자는 토글만 켜면 된다
    - 앱이 프롬프트를 띄우는 API는 샌드박스에서 동작하지 않는다. 먼저 확인하고 막으면 이 경로마저 닫힌다
- **복구 경로**: 프롬프트는 앱당 한 번뿐이고 거부하면 다시 뜨지 않는다.
  메뉴의 `Enable Click…`으로 시스템 설정의 손쉬운 사용 패널을 열어준다
- 권한이 없으면 클릭은 조용히 무시된다 — 앱이 실패를 감지할 방법이 없어 사후에 알릴 수단은 두지 않는다
- 권한을 켠 뒤에도 앱을 재시작하기 전까지 `Enable Click…`이 남는다.
  권한 조회 API가 시작 시점에 고정되어 생기는 제약으로, 우회할 방법이 없어 감수한다

#### 드래그

- 클릭 단축키를 **누르고 있는 동안** 버튼이 눌린 상태로 유지된다 — 창 옮기기 · 텍스트 선택 · 드래그 앤 드롭
- **짧게 누르면 클릭, 누르고 있으면 드래그** — 물리 마우스와 같다.
  클릭도 홀드 방식으로 구현되며, keyDown이 mouseDown, keyUp이 mouseUp이다
- 누른 채 방향 이동을 하면 드래그가 따라간다
    - warp은 이벤트를 만들지 않아 드래그로 인식되지 않는다 ([Notes.md](../Notes.md)).
      드래그 중에는 warp 대신 `mouseDragged`를 보낸다
- 왼쪽 · 오른쪽 모두 같은 방식으로 동작한다
- **클릭 단축키와 방향 단축키는 modifier가 같아야 한다.** 다르면 드래그 중 눌린 modifier 때문에
  방향 단축키가 매칭에 실패한다 — 그래서 모든 Pointer 단축키가 ⌃⌥를 공유한다
- **기본 단축키는 방향키와 키 매트릭스가 겹치지 않는 곳에 둔다.** 겹치면 키보드가 동시 입력을
  유지하지 못해 드래그가 끊긴다 ([Notes.md](../Notes.md))

#### 모니터 간 이동 (⌃⌥C)

v1의 「현재 커서가 위치한 디스플레이의 중앙으로 이동」을 대체한다.

- 누를 때마다 → 다음 모니터의 중앙으로 이동
- 마지막 모니터에서 누르면 첫 모니터로 돌아온다
- **모니터 순서**: 화면 배치 기준 왼 → 오른쪽 (`NSScreen.frame.origin.x`)
- **모니터가 하나면** 항상 그 화면의 중앙 — v1과 동일하게 동작
- 앱은 순번을 기억하지 않는다. 기준은 매번 커서가 놓인 화면 —
  사용자가 마우스를 직접 움직여도 다음에 갈 곳이 어긋나지 않는다
- **커서가 중앙에 있는지는 따지지 않는다.** 중앙일 때만 넘어가게 하면 옆 모니터까지 두 번을 눌러야 하고,
  판정이 좌표 오차에 걸려 넘어가지 못하는 일도 생긴다 ([Notes.md](../Notes.md))
- **커서가 어느 화면에도 속하지 않으면 가장 가까운 화면으로 본다.** 화면 맨 윗줄이 여기에 해당한다

### 설정 창

**설정 창은 둘이고 메뉴 항목도 둘이다** — Keyboard Shortcuts…와 그 아래 Pointer Speed….
한 창에 두 칸으로 담아봤지만 성격이 다른 화면을 나란히 두는 것이라 창을 나눴다.

아래 성질은 두 창이 공유한다.

- 메뉴바 아이콘의 메뉴에서 진입
- 별도 윈도우로 제공
- 초기화 버튼 제공 — 값을 지우는 게 아니라 기본값으로 되돌린다. 각 창은 자기 창의 값만 되돌린다
- 조작하면 즉시 저장
- 완료 누르면 창 이탈
- 창의 신호등 버튼 셋을 모두 감춘다 — 닫는 길은 완료 버튼 하나다
- 타이틀 바를 두지 않는다. 창 크기는 내용에 맞춰 고정되고 스크롤은 생기지 않는다
- 창을 닫으면 앱을 비활성으로 되돌린다 — 직전에 쓰던 앱으로 포커스가 돌아간다
- 창은 다른 앱 위에 떠 있는다 — 값을 바꾸고 곧바로 다른 앱에서 시험할 수 있다

#### 단축키 설정 (Keyboard Shortcuts…)

- Pointer 관련 단축키를 수정할 수 있어야 한다
- 방향키를 UI로 직관적으로 표현

#### 속도 설정 (Pointer Speed…)

- 방향 이동의 속도 곡선을 바꿀 수 있다 — 시작 속도 · 최고 속도 · 최고 속도까지 걸리는 시간
- **그래프로 함께 보여준다.** x축은 시간, y축은 속도
    - 그래프로 바꾸는 것은 가속 모양 하나다 — 3차 베지어 제어점 2개를 끈다
    - **세 값은 슬라이더로만 바꾼다.** 그래프의 시작점 · 끝점은 끌 수 없다
    - 그래프와 슬라이더는 같은 값을 보므로 슬라이더를 움직이면 곡선도 곧바로 따라온다
- **축은 세 값에 맞춰 늘어난다** — 램프를 짧게 줘도 곡선이 한쪽으로 몰리지 않는다
    - **축의 양 끝이 곧 곡선의 양 끝이다.** 램프의 시작점이 좌측 하단, 끝점이 우측 상단 모서리에 닿는다 —
      시간축은 `0…rampDuration`, 속도축은 `base…peak`. 제어점이 그래프 전체를 쓴다
    - 최고 속도에 도달한 뒤의 평탄 구간과 시작 속도 아래쪽은 그래프에 담지 않는다
    - 눈금은 축 구간에 맞춰 매번 고른다. 양 끝은 반올림하지 않아 세 값이 늘 라벨로 보인다
- **감속하는 곡선은 만들 수 없다** — 두 속도가 서로의 벽이 된다.
  시작 속도는 최고 속도에서, 최고 속도는 시작 속도에서 멈춘다
    - 어느 쪽을 끌어도 상대를 밀지 않는다. 밀어내게 하면 한쪽을 끝까지 끌었을 때
      상대 값이 함께 딸려가 되돌릴 수 없다
- 슬라이더를 놓는 즉시 저장된다. 곡선은 키를 누르는 순간 한 번 읽으므로 누르고 있는 도중에 바꿔도
  그 이동은 원래 곡선으로 끝난다
